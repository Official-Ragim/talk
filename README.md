# talk

친구 2~3명이 쓰는 흑백 익명 채팅. GitHub Pages에 올리는 정적 웹 앱입니다.

## 실행

Node.js 24 이상에서:

```sh
npm ci
npm run dev
```

`npm run build`로 `dist/`를 생성합니다. `npm run preview`로 빌드 결과를 확인합니다.

빌드 없이도 정적 서버에서 바로 실행됩니다. `node scripts/serve-static.mjs` 후 `http://127.0.0.1:5174/talk/`를 열면 GitHub Pages와 같은 하위 경로로 확인할 수 있습니다. `vendor/trystero.js`는 의존성을 포함한 배포 파일입니다. 통신 패키지 또는 `scripts/transport.mjs`, `scripts/multipath.mjs`를 수정하면 `npm run vendor`로 다시 생성하고 라이선스 파일과 함께 커밋하세요. 통신 배포 시에는 HTML의 진입 스크립트와 `src/main.js`의 vendor import에 붙인 버전도 함께 갱신해 이전 캐시 사용을 피하세요.

## 검증

`npm test`는 설치된 Microsoft Edge를 사용합니다. Edge가 없는 환경에서는 `npx playwright install chromium` 후 `playwright.config.js`의 `channel: 'msedge'`를 제거하세요. 첫 검사는 UI·모바일·초대 링크를, 두 번째 검사는 독립 브라우저 3개 사이의 실제 WebRTC 통신·문자열 안전 표시·과거 대화 미전달·퇴장/새로고침 삭제를 확인합니다. 실시간 검사는 외부 공개 중계 서버와 WebRTC에 대한 네트워크 접근이 필요합니다.

## 웹에서 파일을 올리는 경우

1. `npm run pack`으로 업로드용 파일을 `github-upload` 폴더에 모읍니다.
2. **github-upload 폴더 안의 내용**을 GitHub 저장소 최상위에 올리고 기존 파일을 덮어씁니다. 폴더 자체를 올리면 안 됩니다.
3. 포함할 항목: `index.html`, `src/`, `vendor/`, `favicon.svg`, `.nojekyll`.
4. **Settings → Pages → Source → Deploy from a branch**, 브랜치 `main`, 폴더 `/(root)`를 선택하고 저장합니다.
5. Pages 배포 완료 후 사이트를 새로고침합니다. 이 방식에는 빌드나 GitHub Actions 설정이 필요하지 않습니다.

이전 버전이 깨진 원인은 빌드 전 HTML이 그대로 배포되고 스크립트가 저장소 경로를 제외한 `/src/main.js`를 참조했기 때문입니다. 현재 버전은 CSS, JavaScript, 통신 라이브러리를 모두 상대 경로의 파일로 불러옵니다. 새 업로드 파일에는 이전 소스의 bare import나 빌드 전용 CSS import가 없습니다.

## Git으로 전체 소스를 관리하는 경우

1. GitHub에 공개 저장소를 만들고 이 프로젝트를 `main` 브랜치에 올립니다.
2. 저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
3. `main`에 push하거나 Actions에서 **Deploy TALK to GitHub Pages → Run workflow**를 실행합니다.
4. 배포가 완료되면 `https://계정.github.io/저장소/`에 접속합니다.

자동 빌드를 사용하려면 로컬 프로젝트의 `.github/workflows/pages.yml`도 함께 올리세요. `vendor/`도 커밋해야 합니다. 상대 경로와 URL 해시 채널을 사용하므로 저장소 하위 경로와 초대 링크 새로고침도 동작합니다. 비밀 키나 환경변수, DB 설정은 없습니다. 무료 GitHub 계정은 공개 저장소의 Pages를 사용할 수 있습니다.

## 사용

- **커스텀 방:** 채널 ID를 입력해서 입장합니다. 다른 IP의 친구와 같은 방에 모일 때도 사용합니다.
- **공용방(IP):** 채널 ID 없이 현재 공인 IPv4를 기준으로 방을 자동 선택합니다. 같은 공인 IPv4로 확인된 참여자끼리 연결되며, 커스텀 방과는 별도 공간입니다. `#mode=ip` 주소는 방문자의 IP방을 선택할 뿐, 원래 방문자의 IP방에 초대하는 링크가 아닙니다.
- 방 종류를 바꾸면 기존 방에서 나가고 내 메시지를 지웁니다. IP방에는 채널 ID 입력과 초대 링크 복사 기능을 표시하지 않습니다.
- 원하는 채널명을 영문(A–Z, a–z)·숫자(0–9) 1~32자로 입력하고 **입장 / 만들기**를 누릅니다. 한글·공백·특수문자는 허용하지 않으며, 대소문자는 구분하지 않습니다. 같은 이름으로 입장한 사람끼리 연결됩니다.
- 같은 IP의 접속을 제한하지 않습니다. 같은 와이파이의 기기, 같은 브라우저의 여러 탭도 문서별 임의 peer ID로 각각 구분합니다. 두 탭과 별도 브라우저 세션을 같은 PC에서 연결해 검증합니다. 네트워크의 WebRTC 차단이나 공유기의 기기 간 격리는 별개의 연결 제한입니다.
- 닉네임을 생략하면 매 입장 시 임의의 익명 이름을 부여합니다. 이름은 인증되지 않으므로 서로 같을 수 있습니다.
- 무작위 채널은 96비트 무작위 부분을 사용합니다. 입장 후 우측 상단 복사 버튼으로 링크를 공유하세요.
- 초대받은 사람은 링크를 열고 **입장 / 만들기**를 누릅니다. 이전에 만든 하이픈 포함 채널 링크는 새 이름 규칙에 맞지 않아 다시 만들어야 합니다.
- 연결된 참여자가 있을 때만 전송할 수 있습니다. Enter로 전송하고 Shift+Enter로 줄바꿈합니다. 한글 조합 중 Enter는 전송하지 않습니다.
- 나가거나 새로고침하면 내 화면의 대화가 지워집니다. 새로운 입장자에게 과거 메시지를 전송하지 않습니다.

## 참가자 DM

- 커스텀 방과 IP방 모두 **접속자 목록에서 상대 이름**을 누르면 DM이 열립니다. 내 이름으로는 DM을 시작할 수 없습니다. 모바일에서도 접속자 목록이 표시됩니다.
- DM은 선택한 상대만 복호화할 수 있도록 암호화해 전송합니다. 직접 연결이 없으면 공통으로 연결된 참가자가 암호문만 전달하며 그 참가자의 채팅·DM 화면에는 나타나지 않습니다. 상대 화면을 자동으로 열지 않으며, 참가자 이름 옆에 `DM 대기` 또는 읽지 않은 메시지 수가 표시됩니다.
- `DM 나가기` 또는 Escape로 퇴장합니다. 한 명이 DM에 남아 있는 동안에는 메모리에 대화를 유지하고 다시 열 수 있습니다. **두 사람 모두 DM을 나가면 양쪽의 DM 기록을 삭제합니다.** 이 규칙은 상대가 아직 DM을 열지 않은 경우에도 적용됩니다.
- 상위 채팅방 퇴장·모드 변경·새로고침은 내 모든 DM을 즉시 지웁니다. 상대가 상위 방을 나가면 전송을 막고, 남아 있는 사람이 DM을 닫을 때 그쪽 기록도 삭제합니다. 새로고침한 브라우저에 이전 DM을 복구하지 않습니다.
- 최근 메시지 300개만 메모리에 보관합니다. 서버나 브라우저 저장소에 기록하지 않습니다.

## 미니게임: DEPOT / 창고 구역

1. **공용방(IP) 또는 커스텀 방에 입장 → 미니게임 방 입장**을 누릅니다. 같은 채팅방에서 게임방에 별도로 들어온 사람끼리 만납니다. IP방은 FFA만, 커스텀 방은 FFA와 팀전을 지원합니다.
2. 로비에서 무기를 고르고 **출격하기**를 누릅니다. 1명일 때는 연습할 수 있고, 다른 사람이 출격하면 함께 FFA 전투를 합니다. 채팅만 하는 참가자는 전투에 포함되지 않습니다.
3. **내 조작 모드**에서 컴퓨터 / 모바일을 각자 고릅니다. 컴퓨터 모드는 WASD 이동, 마우스 조준, 왼쪽 클릭 또는 Space 사격, R 또는 버튼 재장전입니다. 모바일 모드는 화면 이동 패드와 드래그/터치를 사용하며 적이 조준점에 들어오면 자동 사격합니다. 컴퓨터에서도 모바일 모드를 골라 마우스로 패드와 드래그를 사용할 수 있습니다.
4. 체력 100, 사망 3초 후 부활, 부활 보호 1.5초(사격 시 해제), 20킬 달성 시 승리입니다. 승리 후 8초 뒤 점수를 초기화하고 다음 라운드를 시작합니다.
5. **장비 변경**은 전투에서 빠져 로비로 돌아갑니다. 다시 출격하면 개인 점수는 초기화됩니다. **게임방 나가기** 또는 Escape는 게임만 종료하며 IP 채팅방에는 남습니다.

| 무기 | 피해 | 탄창 | 사격 / 재장전 |
| --- | --- | --- | --- |
| M870 | 산탄 8개 × 16, 최대 사거리 360 | 8발 | 0.85초 간격 펌프 액션 / 2.6초 |
| M4 Carbin | 25 | 30발 | 누르고 있으면 0.12초 간격 자동 사격 / 1.9초 |
| Desert Eagle | 50, 보호가 끝난 체력 100 상대를 두 발로 처치 | 7발 | 클릭마다 한 발, 최소 0.42초 간격 / 1.8초 |

맵은 창고·적재장·골목·엄폐물로 만든 독자적인 3D 맵입니다. 벽은 이동과 총알을 막습니다. 탄약이 비면 자동 재장전하며, 재장전 중에는 사격할 수 없습니다. 탄창 밖의 예비 탄약은 무제한입니다.

### 게임 시점과 시야각

- **게임방에 처음 입장한 사람이 방장**이며 `게임 시점 → 3D 탑뷰 / 3D 1인칭`을 선택합니다. IP방과 커스텀 방 모두 지원하며, 방장의 선택이 모든 참가자와 나중에 입장한 사람에게 동일하게 적용됩니다. 출격/준비 중에는 시점 변경을 잠그고, 모두 로비로 돌아오면 변경할 수 있습니다.
- 방장이 나가면 남은 사람 중 먼저 입장한 사람이 방장을 이어받습니다. 재입장한 전 방장이 권한을 되찾지는 않습니다. 입장 순서는 이미 알려진 게임 참가자들의 논리적 순서 다음으로 부여하며, 동시에 게임방을 만든 경우에만 시작 시각과 peer ID로 순서를 결정합니다.
- **내 시야각 FOV** 슬라이더로 55~110도를 조절합니다. 수직 시야각 기준이며, 각자 화면에만 적용되고 다른 참가자의 설정은 바꾸지 않습니다. 탑뷰에서는 값이 커질수록 더 넓은 구역을 볼 수 있습니다.
- **3D 탑뷰:** 입체 전장을 위에서 비스듬히 내려다봅니다. 카메라는 맵 가장자리에서 이동 범위를 제한해 바깥 공간만 보이지 않게 하며, 마우스 위치 또는 화면 터치 지점으로 조준합니다.
- **3D 1인칭:** 전장을 클릭해 마우스를 잠근 뒤 마우스로 좌우·상하 시점을 회전합니다. WASD는 바라보는 방향 기준으로 이동합니다. 왼쪽/오른쪽 방향키로도 회전할 수 있습니다. Esc는 먼저 마우스 잠금을 풀고, 잠금이 풀린 상태에서 다시 Escape를 누르면 게임방을 나갑니다.
- 모바일 모드의 1인칭은 전장 드래그로 시점을 돌리고 마우스를 잠그지 않습니다. 컴퓨터 모드에서 마우스 잠금이 불가능하면 드래그 조준과 Space 사격을 사용할 수 있습니다. 상하 조준은 총알 높이에 반영되어 적 머리 위나 바닥을 향해 쏘면 적중하지 않습니다. 캐릭터 높이에 맞춘 Desert Eagle은 기존처럼 두 발 처치입니다.
- WebGL로 동일한 입체 벽·캐릭터·총기 모델을 렌더링하며 외부 3D 라이브러리 다운로드가 필요하지 않습니다. WebGL을 사용할 수 없으면 안내 메시지를 표시하고 출격을 중단합니다. 그래픽 연결이 끊기면 로비로 돌아와 복구 후 다시 출격할 수 있습니다.

### 정밀 조준과 성능 설정

- 터치 기기에서는 기본으로 모바일 모드를 선택합니다. 화면 너비에 따라 조작이 갑자기 바뀌지 않으며, **내 조작 모드**에서 언제든 변경할 수 있습니다. 방장이 고르는 공통 3D 시점과 개인 조작 모드는 별개입니다.
- 모바일 모드에는 사격 버튼이 없습니다. 1인칭은 중앙 조준선이 적 몸에 닿을 때, 탑뷰는 조준점이 적 위치에 닿을 때 자동 발사합니다. 호스트가 벽·사거리·높이·아군·부활 보호를 검사하며 총기별 발사 간격과 탄약·재장전 규칙을 그대로 적용합니다. 화면이 숨겨지거나 포커스를 잃으면 자동 사격 입력을 끕니다.

- PC에서는 **우클릭 또는 Shift를 누르는 동안** 정밀 조준합니다. 화면의 **정밀 조준** 버튼과 모바일 **조준** 버튼은 한 번 누르면 켜지고 다시 누르면 꺼집니다. 우클릭을 유지한 채 왼쪽 버튼으로 사격할 수 있습니다.
- 조준 시 화면이 부드럽게 확대되고 1인칭 마우스·드래그 감도가 절반으로 줄어듭니다. 1인칭 총기도 화면 중앙으로 이동합니다. 개인 FOV 슬라이더 값은 그대로 유지하며 조준을 풀면 원래 시야각으로 돌아옵니다.
- 조준 중 이동 속도는 기본의 65%, 탄 퍼짐은 M4가 기본의 40%, M870이 80%입니다. 총기 피해는 그대로이며 Desert Eagle은 체력 100 상대를 기존처럼 두 발로 처치합니다. 재장전·사망·준비 대기 중에는 조준이 적용되지 않고, 창 전환·마우스 잠금 해제·퇴장 시 조준 입력을 해제합니다.
- 전투 화면의 **화질 → 자동 / 성능 우선 / 선명하게**를 각자 선택합니다. 자동은 프레임 간격에 따라 해상도를 조절하고, 성능 우선은 낮은 해상도로 그래픽 부담을 줄입니다.
- 지형·총기 모델과 그래픽 버퍼를 재사용하고, 캐릭터·탄흔·점수판은 바뀐 경우에만 갱신합니다. 보이지 않는 탭은 화면 렌더링을 멈춥니다. 같은 입력의 반복 전송을 줄이고, 느린 상대에게 보낼 게임 상태는 최신 대기 상태 하나만 유지합니다.
- `tests/performance.spec.js`의 12명·60프레임·15회 위치 갱신 조건에서 그래픽 데이터 전송량은 약 8.16MB에서 1.93MB로 줄었습니다. 이 수치는 해당 렌더링 작업량 비교이며 실제 FPS나 인터넷 지연 개선율을 뜻하지 않습니다. `npm run test:arena`는 조준 속도·탄 퍼짐·재장전과 느린 수신자 전송 큐를, 브라우저 검사는 PC·모바일 조준과 화질 변경을 함께 검증합니다.

### 커스텀 방의 n vs n 팀전

- 게임 로비에서 **게임 방장**이 `게임 방식 → n vs n 팀전`을 고르고 팀당 인원을 선택합니다. 1 vs 1부터 6 vs 6까지 가능합니다. FFA로 다시 변경할 수도 있습니다. 누군가 출격/준비한 동안은 방식과 인원 변경을 잠그며, 모두 **장비 변경 / 준비 해제**로 로비에 돌아오면 변경할 수 있습니다.
- 참가자는 **자동 배정 / 레드 팀 / 블루 팀**을 선택합니다. 게임 방장이 좌석을 확정하며, 먼저 배정된 참가자를 유지하고 팀별 정원을 초과하지 않습니다. 좌석이 없으면 로비에서 기다리거나 다른 팀을 선택합니다.
- 양 팀에서 지정 인원만큼 **준비 / 출격**해야 전투가 시작됩니다. 예를 들어 2 vs 2는 레드 2명, 블루 2명이 모두 준비해야 합니다. 인원이 부족하거나 중간에 누군가 준비를 해제·퇴장하면 이동·사격·경기 시간이 멈추고 준비 대기를 표시합니다. 다시 채워지면 이어집니다.
- 레드는 맵 왼쪽, 블루는 오른쪽에서 부활합니다. 캐릭터·이름·점수판에 팀을 표시하고, 아군에게는 피해를 주지 않습니다. **개인 킬과 별도로 팀 합산 20킬**을 달성하면 그 팀이 승리합니다. 다음 라운드에는 개인·팀 점수를 초기화합니다.
- 호스트 변경 시 시점·FFA/팀전·팀당 인원 설정은 이어받고 라운드와 점수는 초기화합니다. 모두 게임방을 나가면 설정도 기본 FFA·3D 탑뷰로 돌아갑니다. IP방에는 팀전 선택을 노출하지 않고 수신하는 팀전 설정도 거부합니다.

게임방에 먼저 입장한 방장의 브라우저를 호스트로 사용해 이동·명중·피해·점수·부활을 계산하고 참가자에게 상태를 보냅니다. 호스트가 변경되면 새 호스트에서 라운드와 점수를 초기화하며 화면에 안내합니다. 모든 사람이 나가면 게임 상태도 사라집니다. 공개 신호 서버는 연결 협상에만 사용합니다. 게임 서버가 없는 P2P 구조이므로 호스트 브라우저의 백그라운드 제한·네트워크 지연이 전투에 영향을 줄 수 있고, 변조한 클라이언트를 차단하는 서버 측 안티치트는 제공하지 않습니다.

`npm run test:arena`는 총기 피해·엄폐·충돌·재장전·부활·라운드 종료와 1~6명 팀 정원·동시 좌석 요청·준비 대기·아군 피해 방지·팀 승리, 최초 입장자 권한·FOV 투영·1인칭 이동·상하 명중 판정을 검증합니다. `npm test`는 기존 채팅 검사와 함께 실제 브라우저 2~4개에서 DM 비공개 전송·기록 수명, 게임 별도 입장·원격 무기 입력·호스트 퇴장·모바일 화면, 커스텀 FFA 및 팀전 설정·준비·동기화, WebGL 렌더링·공통 시점·개별 FOV·마우스 잠금과 Esc 해제를 검사합니다.

## 저장과 익명성의 정확한 범위

메시지, 닉네임, 참여자는 브라우저 메모리에만 존재합니다. localStorage, sessionStorage, IndexedDB, 쿠키, 대화 서버, 분석 도구를 사용하지 않습니다. 대화 화면은 최근 300개 항목만 유지합니다.

**상위 채팅방에서 내가 나가면 내 기록만 삭제됩니다.** 다른 사람이 채널을 열어 두었다면 그 사람 화면에는 기록이 남습니다. 마지막 참여자가 나가면 앱이 유지하는 메시지는 사라집니다. DM 창만 나갈 때의 수명은 위의 DM 규칙을 따릅니다. 상대가 따로 복사하거나 캡처한 것은 삭제하지 못합니다. 저장소 없는 P2P에서 모든 사람의 기록을 강제 삭제하거나 악의적인 클라이언트의 저장을 막는 것은 보장하지 않습니다.

**로그인 없는 익명이며, 네트워크 익명화 서비스는 아닙니다.** GitHub Pages는 접속 IP를 기록할 수 있습니다. 공개 신호 중계 서버와 STUN 서비스에도 연결 메타데이터가 노출될 수 있습니다. 직접 연결된 상대에게 IP가 노출될 수 있습니다. 채널명을 아는 사람은 누구나 입장합니다. 짧고 추측 가능한 이름보다 무작위 채널을 권합니다. 닉네임은 인증된 신원이 아닙니다.

### IP방의 동작

IP방 입장 버튼을 누를 때만 [ipify의 IPv4 API](https://www.ipify.org/)에 요청합니다. ipify는 이 요청의 접속 IP를 알 수 있습니다. 커스텀 방이나 단순 모드 선택에서는 IP API에 요청하지 않습니다. 8초 안에 응답하지 않거나 응답이 유효한 IPv4가 아니면 입장을 중단하고 재시도 또는 커스텀 방을 안내합니다. 조회 중 모드를 바꾸면 요청을 취소합니다.

IPv6는 같은 공유기의 기기끼리도 주소가 다를 수 있으므로 IPv4 전용 API를 사용합니다. IPv4 접근이 안 되거나 IP 조회 서비스가 차단된 환경에서는 커스텀 방을 사용해야 합니다. VPN·프록시·통신사 CGNAT에 따라 서로 다른 장소의 사람이 같은 공인 IP를 공유하거나, 같은 장소에서도 다른 공인 IP를 쓸 수 있습니다.

브라우저에서 공인 IPv4의 SHA-256을 계산하고 `ip:` 접두어가 있는 별도 방 ID로 연결합니다. 원래 IP나 해시를 URL이나 채팅 UI에 표시하거나 브라우저 저장소에 보관하지 않습니다. **해시는 IP 익명화나 접근 제어가 아닙니다.** IPv4는 범위가 작아 추측할 수 있고, 별도의 서버 인증이 없으므로 코드를 변경한 클라이언트가 특정 IP방에 접속하는 것을 강제로 차단하지 않습니다. IP방은 자동 그룹 분류이며 사설망 전용 보안 채팅이 아닙니다.

## 무료 통신 구조와 한계

최초 참가자의 Nostr 검색 경로가 막혀도 참가자가 합류할 수 있도록 MQTT 검색을 동시에 사용합니다. 두 경로에서 발견한 같은 peer ID는 한 명으로 합치고 실제 메시지는 사용 가능한 WebRTC 경로 하나로만 보냅니다. 한 검색 경로가 실패하거나 연결이 끊겨도 나머지 연결이 살아 있으면 참가자를 퇴장시키지 않습니다. 이 기능은 연결 협상 경로를 보완하며 WebRTC 자체가 차단된 환경의 TURN 대체 기능은 아닙니다.

방을 나간 직후 같은 채널에 다시 입장할 때는 이전 통신 객체의 비동기 퇴장이 끝난 뒤 새 방을 연결합니다. 대기 중 취소하거나 다른 방 종류로 바꾸면 이전 입장 요청은 실행하지 않습니다. `tests/connection.spec.js`는 빠른 방 재생성, 대기 중 입장 취소, 생성자의 기본 검색을 차단한 조건에서 양쪽 입장 순서와 메시지 송수신을 검사합니다.

참가자 사이의 직접 연결 일부가 빠져도 공통 연결이 있으면 그 경로로 참가자 정보·채팅·DM·게임 상태를 전달합니다. 예를 들어 A–B와 B–C만 연결되어 있어도 A와 C는 B를 통해 통신합니다. 목적지가 있는 모든 메시지는 입장 시 생성한 ECDH P-256 키와 AES-GCM으로 암호화해 중간 참가자가 내용을 읽지 못하게 합니다. 닉네임은 인증 수단이 아니며 이 구조가 계정 인증을 제공하지는 않습니다.

연결 목록을 주기적으로 실제 WebRTC 연결과 맞추고, 닉네임·게임 입장 상태도 다시 알립니다. 연결 이벤트 누락과 초기 정보 교환 순서 차이를 복구하며, 백그라운드 탭의 타이머 지연만으로 연결된 사람을 퇴장시키지 않습니다. 이전 메시지는 새 연결에 재전송하지 않습니다. 서로 연결된 경로가 전혀 없는 두 그룹은 이 기능만으로 연결할 수 없습니다.

통신 형식 변경으로 **참가자 전원이 새로고침하고 다시 입장해야** 새 버전끼리 만날 수 있습니다. 구버전 탭은 별도 통신 공간을 사용합니다. `npm run test:mesh`와 `tests/mesh.spec.js`는 직접 연결 하나가 빠진 3명 통신, 누락된 연결 이벤트 복구, 양방향 메시지와 비공개 DM, 게임 참가자 동기화 및 퇴장을 검증합니다.

```
GitHub Pages ── 정적 HTML / CSS / JS ── 각 브라우저
공개 Nostr / MQTT 중계 ── 상대 발견 / WebRTC 연결 협상
브라우저 A ←── 암호화된 WebRTC 데이터 채널 ──→ 브라우저 B
```

[Trystero](https://github.com/dmotz/trystero)와 `@trystero-p2p/mqtt` 0.25.4를 함께 사용합니다. 대화 내용은 공개 Nostr 게시물이나 MQTT 검색 토픽으로 전송하지 않으며, 연결 이후 브라우저끼리 주고받습니다. 신호 중계 사업자가 연결 메타데이터를 보관하지 않는다는 보장은 없습니다. 모든 참여자가 **동일한 사이트 주소**를 이용해야 같은 앱 공간에 들어갑니다.

운영자가 별도 서버·유료 요금제·DB를 준비하지 않아도 시작할 수 있지만, 무료 공개 중계 서비스의 가용성은 보장되지 않습니다. 일부 통신사 NAT 또는 학교·회사 방화벽에서는 WebRTC 직접 연결이 실패할 수 있습니다. 기본 버전에 TURN 서버는 포함하지 않았습니다. 실제 친구들의 네트워크에서 연결이 안 되면 TURN 중계 또는 별도 WebSocket 서버를 추가해야 합니다. TURN이 필요한 경우 장기 비밀키를 공개 코드에 넣지 말고, 별도 서버에서 만료되는 접속 정보를 발급해야 합니다.

오프라인 큐와 메시지 재전송·기록 동기화는 없습니다. 재연결 시 끊긴 동안의 메시지는 복구되지 않습니다. 메시지의 ‘전송됨’은 데이터 전송 완료 표시이며 상대방의 읽음 확인이 아닙니다.
