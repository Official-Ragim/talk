# TALK.

친구 2~3명이 쓰는 흑백 익명 채팅. GitHub Pages에 올리는 정적 웹 앱입니다.

## 실행

Node.js 24 이상에서:

```sh
npm ci
npm run dev
```

`npm run build`로 `dist/`를 생성합니다. `npm run preview`로 빌드 결과를 확인합니다.

## 검증

`npm test`는 설치된 Microsoft Edge를 사용합니다. Edge가 없는 환경에서는 `npx playwright install chromium` 후 `playwright.config.js`의 `channel: 'msedge'`를 제거하세요. 첫 검사는 UI·모바일·초대 링크를, 두 번째 검사는 독립 브라우저 3개 사이의 실제 WebRTC 통신·문자열 안전 표시·과거 대화 미전달·퇴장/새로고침 삭제를 확인합니다. 실시간 검사는 외부 공개 중계 서버와 WebRTC에 대한 네트워크 접근이 필요합니다.

## GitHub Pages 배포

1. GitHub에 공개 저장소를 만들고 이 프로젝트를 `main` 브랜치에 올립니다.
2. 저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
3. `main`에 push하거나 Actions에서 **Deploy TALK to GitHub Pages → Run workflow**를 실행합니다.
4. 배포가 완료되면 `https://계정.github.io/저장소/`에 접속합니다.

`.github/workflows/pages.yml`에 자동 배포가 준비되어 있습니다. Vite의 상대 경로와 URL 해시 채널을 사용하므로 저장소 하위 경로와 초대 링크 새로고침도 동작합니다. 비밀 키나 환경변수, DB 설정은 없습니다. 무료 GitHub 계정은 공개 저장소의 Pages를 사용할 수 있습니다. 이 작업에서는 원격 저장소를 만들거나 실제 배포하지 않았습니다.

## 사용

- 같은 채널명으로 입장합니다. 영문은 소문자로 정규화합니다.
- 닉네임을 생략하면 매 입장 시 임의의 익명 이름을 부여합니다. 이름은 인증되지 않으므로 서로 같을 수 있습니다.
- 무작위 채널은 96비트 무작위 부분을 사용합니다. 입장 후 우측 상단 복사 버튼으로 링크를 공유하세요.
- 초대받은 사람은 링크를 열고 **초대받은 채널 입장**을 누릅니다.
- 연결된 참여자가 있을 때만 전송할 수 있습니다. Enter로 전송하고 Shift+Enter로 줄바꿈합니다. 한글 조합 중 Enter는 전송하지 않습니다.
- 나가거나 새로고침하면 내 화면의 대화가 지워집니다. 새로운 입장자에게 과거 메시지를 전송하지 않습니다.

## 저장과 익명성의 정확한 범위

메시지, 닉네임, 참여자는 브라우저 메모리에만 존재합니다. localStorage, sessionStorage, IndexedDB, 쿠키, 대화 서버, 분석 도구를 사용하지 않습니다. 대화 화면은 최근 300개 항목만 유지합니다.

**내가 나가면 내 기록만 삭제됩니다.** 다른 사람이 채널을 열어 두었다면 그 사람 화면에는 기록이 남습니다. 마지막 참여자가 나가면 앱이 유지하는 메시지는 사라집니다. 상대가 따로 복사하거나 캡처한 것은 삭제하지 못합니다. 저장소 없는 P2P에서 모든 사람의 기록을 강제 삭제하거나 악의적인 클라이언트의 저장을 막는 것은 보장하지 않습니다.

**로그인 없는 익명이며, 네트워크 익명화 서비스는 아닙니다.** GitHub Pages는 접속 IP를 기록할 수 있습니다. 공개 신호 중계 서버와 STUN 서비스에도 연결 메타데이터가 노출될 수 있습니다. 직접 연결된 상대에게 IP가 노출될 수 있습니다. 채널명을 아는 사람은 누구나 입장합니다. 짧고 추측 가능한 이름보다 무작위 채널을 권합니다. 닉네임은 인증된 신원이 아닙니다.

## 무료 통신 구조와 한계

```
GitHub Pages ── 정적 HTML / CSS / JS ── 각 브라우저
공개 Nostr 중계 서버 ── 상대 발견 / WebRTC 연결 협상
브라우저 A ←── 암호화된 WebRTC 데이터 채널 ──→ 브라우저 B
```

[Trystero](https://github.com/dmotz/trystero) 0.25.4의 Nostr 전략을 사용합니다. 대화 내용은 공개 Nostr 게시물로 전송하지 않으며, 연결 이후 브라우저끼리 주고받습니다. 신호 중계 사업자가 연결 메타데이터를 보관하지 않는다는 보장은 없습니다. 모든 참여자가 **동일한 사이트 주소**를 이용해야 같은 앱 공간에 들어갑니다.

운영자가 별도 서버·유료 요금제·DB를 준비하지 않아도 시작할 수 있지만, 무료 공개 중계 서비스의 가용성은 보장되지 않습니다. 일부 통신사 NAT 또는 학교·회사 방화벽에서는 WebRTC 직접 연결이 실패할 수 있습니다. 기본 버전에 TURN 서버는 포함하지 않았습니다. 실제 친구들의 네트워크에서 연결이 안 되면 TURN 중계 또는 별도 WebSocket 서버를 추가해야 합니다. TURN이 필요한 경우 장기 비밀키를 공개 코드에 넣지 말고, 별도 서버에서 만료되는 접속 정보를 발급해야 합니다.

오프라인 큐와 메시지 재전송·기록 동기화는 없습니다. 재연결 시 끊긴 동안의 메시지는 복구되지 않습니다. 메시지의 ‘전송됨’은 데이터 전송 완료 표시이며 상대방의 읽음 확인이 아닙니다.
